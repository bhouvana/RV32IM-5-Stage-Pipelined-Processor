# ADR 0022: MMU — Sv32 (Phase F of the second wave)

## Problem

After the five-phase redesign (`docs/adr/0018`-`0021`) closed out, the user asked to continue with
the rest of `docs/ROADMAP.md`'s Phase 5 backlog: caches, an MMU, and dual-issue — all three,
confirmed via `AskUserQuestion` (the most ambitious option, consistent with every phase so far).
Sequenced as three new phases (MMU → caches → dual-issue), since caching needs to know whether
addresses are virtual or physical before it can be designed at all, and dual-issue is best attempted
against an already-settled memory hierarchy.

Partway through this phase (after F1-F4 groundwork had landed), the user supplied a long-range
10-generation roadmap (`docs/ROADMAP_VISION.md`) and explicitly rejected "just keep finishing F/G/H
because they were queued" in favor of "build whatever Generation 1 actually needs." The resulting
scope decision (confirmed via `AskUserQuestion`, see `docs/ROADMAP_VISION.md`'s "Generation 1 scope"
section): finish Phase F to F9 anyway — not itself a Generation 1 item (it's Generation 3's), but
cheap to close out with F1-F5 already done, and real groundwork for later — while Phase H
(dual-issue) is dropped entirely (never a Generation 1 item, no sunk cost) and Phase G (caches)
continues since it matches Generation 1's I$/D$ items directly. This ADR covers Phase F's full F1-F9
story; Phase G is genuinely separate future work, not covered here.

Research (two parallel Explore agents, before any design) confirmed the actual shape of the problem:

- **This core has zero privilege-mode state anywhere** — M-mode was architecturally implicit, not
  encoded, and `mstatus`/`mie`/`mip` had zero spare real bits, so new S-mode fields needed genuinely
  new flip-flops, not unmasking existing ones.
- **The PC-input redirect mux had already been extended twice** (interrupts — `docs/adr/0020`'s D9;
  branch misprediction — `docs/adr/0021`'s E4) and needed a third, careful extension for
  privilege-aware trap delegation, following the same "extend the existing priority chain, never
  invent a second one" lesson both prior extensions already learned the hard way.
- **The Wishbone bus is strictly single-master today**, so a page-table walker can't be a second
  concurrent master without either a real arbiter or (the design choice made) a plain mux — safe
  because a walk only ever happens while the pipeline is already stalled waiting for it, so there is
  never genuine concurrent bus contention to arbitrate.
- **Critically, unlike branch prediction's zero-ISS-change case, the independent ISS oracle needs a
  from-scratch page-table walker matching the RTL bit-for-bit** — address translation affects every
  memory access, not scheduled points the way interrupts or mispredictions are. This was flagged up
  front as the single hardest verification-tooling task in the project's history (F6, below).

Three scope decisions confirmed with the user (`AskUserQuestion`, most ambitious each time): **all
three of caches+MMU+dual-issue** (not just caches+MMU, at the time this was decided), **full Sv32**
(not PMP-only), **I$+D$ set-associative write-back caches** for the later Phase G. Further
low-controversy defaults set without a separate question (documented here, not re-litigated per
step): a **unified TLB** (one array, two independent combinational read ports — fetch-side,
load/store-side — cheap in behavioral Verilog, no separate I-TLB/D-TLB module needed), the **PTW
shares the LSU's bus port via a mux, not a real arbiter**, **`sfence.vma` always flushes the whole
TLB** (no selective invalidation by `rs1`/`rs2`, unconditional per the phase's own scoping default),
**M-mode always bypasses translation** (`mstatus.MPRV` out of scope), and **no SUM/MXR bits
implemented** (S-mode can therefore never access U-accessible pages — the literal SUM=0 default
behavior, just with no toggle to change it; a real, spec-legal, documented simplification, not an
oversight).

This made Phase F nine independently-verified steps (F1-F9), each ending with the full suite passing
again, per this project's established convention.

## Design

### F1-F3: privilege-mode CSR state and trap delegation (state only, no MMU yet)

`riscv_defs.vh` gained every new CSR address (`SSTATUS`/`SIE`/`STVEC`/`SSCRATCH`/`SEPC`/`SCAUSE`/
`STVAL`/`SIP`/`SATP`/`MEDELEG`/`MIDELEG`/`MTVAL`), new `MCAUSE` page-fault causes (12/13/15) and
privilege-dependent ecall causes, privilege encoding (`PRIV_U`/`PRIV_S`/`PRIV_M`), every new
`mstatus`/`mie`/`mip` bit position, and Sv32 PTE/VPN layout constants. `CSR.v` gained a `priv_mode`
register (resets to `PRIV_M`, spec boot behavior) and real storage for every new S-mode register.
**A real, non-obvious design point**: `sstatus`/`sie`/`sip` are not separate storage — they're masked
*views* onto `mstatus`/`mie`/`mip`'s S-visible bit subset (mirrors `fcsr`'s existing view-of-
`{frm,fflags}` relationship), but the S-visible bit positions are genuinely independent bit indices
from the machine-level ones, not aliases — real spec behavior. `mip`'s new bits (`SSIP`/`STIP`/`SEIP`)
are, per spec, software-writable (unlike the existing hardware-driven read-only `MTIP`/`MEIP`),
needing a new `mip_sw` register ORed with the hardware pending wires at read time.

`Control.v` gained `isSret`/`isSfenceVma` decode. **A real, non-obvious encoding subtlety**:
`sfence.vma` is SYSTEM/funct3=000 like `ecall`/`ebreak`/`mret`/`sret`, but unlike those four it has
real `rs1`/`rs2` register fields, so its `inst[31:20]` position is not a single fixed value — it
varies with whichever `rs2` register the encoding happens to name. Fixed by checking `funct7`
(`inst[31:25]`) alone, before falling into the fixed-immediate case for the other four.

The actual privilege-aware trap entry/exit machinery: `CSR.v` gained `trap_target_is_s` (computed
from `mideleg`/`medeleg`/`priv_mode` — a trap sourced *in* M is never delegated regardless of the
bits, per spec; only a trap at or below S can be delegated to S), dual M/S chains for `epc`/`cause`/
`tval` and `mstatus`'s `MIE`↔`MPIE` vs. `SIE`↔`SPIE` swap, and real `mret`/`sret` behavior.
`riscvpipeline.v` gained `csr_priv_violation`, `mret_priv_violation`, `sret_priv_violation` — all
three fold into `exception_taken` as ordinary illegal-instruction causes.

### F4: `design/Tlb.v` + `design/Ptw.v`, standalone

Both new modules, standalone (not yet wired into the live pipeline — F5's job), each independently
verified before pipeline integration, mirroring `docs/adr/0021`'s own `Bht.v`/`Btb.v` precedent.
`Tlb.v`: small, direct-mapped, unified array with two independent combinational read ports.
`Ptw.v`: a `busy`/`done` two-level Sv32 walker mirroring `Divider.v`'s own interlock shape
(`start && !busy && !done` guard, latching its inputs once at walk start).

### F5: wiring Tlb.v + Ptw.v live — the hardest single step in this phase

Translation is gated on `satp.MODE==Sv32 && priv_mode != M` (M-mode always physical). Two independent
interception points: fetch (`imem_read_addr`) and load/store — intercepted at EX's raw `ALUOut`
(pre-reg3-latch), a deliberate deviation from the plan's literal MEM-stage wording, so a D-side page
fault can reuse the *existing* EX-anchored `exception_taken`/`unconditional_redirect` machinery
directly rather than inventing a second, MEM-anchored redirect category. This makes D-side translation
architecturally identical in shape to `div_stall`/`fp_stall` (hold `reg2`, bubble `reg3`) rather than
`mem_stall` — simpler, and reuses a shape this codebase had already verified three times.

I-side: `itlb_miss` folds into both `pc_stall` and `reg2`'s `flush`, the same two-place fold
`Hazard.v`'s own stall already uses. A fault flag (`ifetch_fault`) threads through `reg1`/`reg2` in
the decode-context group (squash-to-0 on redirect, hold on stall, survives an unrelated load-use
flush) so a garbage fetched instruction can never have a side effect.

D-side: `dtlb_miss` folds into `reg2_hold` (alongside `div_stall|mem_stall|fp_stall`) and `pc_stall`;
`reg3_bubble` gains `dtlb_miss`. Translated physical address substitution replaces `ALUOut` in
`ex_result`'s load/store arm — bit-exact at `translate_enable=0`.

Shared walker arbitration: D-side always wins when both are pending (older instruction, program-order
priority). A one-bit register (`ptw_servicing_d_r`) remembers which side a walk was launched for,
since `Ptw.v` itself doesn't report this.

`sfence.vma`: `sfence_priv_violation` (requires S or M) folds into `exception_taken`;
`sfence_real` fires an unconditional whole-TLB flush, gated `!reg2_hold` (fire exactly once).

## Real design findings, caught by tracing and by running

Matching this project's own "hand-trace before trusting a first design" precedent
(`docs/adr/0009`, reused every phase since), F5's design doc traced four required interaction checks
before writing RTL and found them all already safe by construction (reg1's squash-before-stall
priority, `HazardNoForward`'s generic `!branch_taken` stall suppression, `redirect_squash_extend_r`'s
profile-1 generalization, and D-side forwarding/hazard checks against a `reg2`-held load). Unlike
`docs/adr/0021`'s branch predictor, though, F5 did not ship clean on the first run — six real bugs
were found by *running* the design, debugged with a throwaway testbench (`sim/tb/tb_mmu_debug.v`)
using hierarchical `$display` taps on internal signals (`dut.pc_o`, `dut.m_Ptw.state`/`vpn0_r`/
`pte_r`, etc.), the same technique this project's own bug hunts (Phase D8/D11) already established:

1. **`PC.v` prioritizes `stall` over accepting a redirect unconditionally** — a younger instruction's
   `itlb_miss` silently swallowed an older instruction's exception redirect from firing, the exact bug
   class `docs/adr/0016` first found for `HazardNoForward.v`'s own stall. Fixed: gated `itlb_miss`/
   `dtlb_miss` on `&& !branch_taken`.
2. **X-propagation from `Tlb.v`'s unfilled array entries.** `Tlb.v` only resets its `valid` array (by
   design), not `ppn_r`/`tag` — using the PPN unconditionally on a miss let X flow into `inst`,
   corrupting unrelated combinational signals (observed: `Hazard.v`'s own stall went to X). Fixed:
   gated the physical-address substitution on the real hit signal, not just `translate_enable`.
3. **An in-flight `Ptw.v` walk isn't cancelled by an intervening redirect** — its stale result was
   still trusted several cycles later against unrelated, already-redirected-to code. Fixed: a new
   `ptw_abandoned_r` latch (set when a redirect coincides with `ptw_busy`), gating the *fault*
   outcome but not a stale *successful* fill (still useful).
4. **`RamWishboneAdapter.v`'s `funct3` side-band port was never muxed for `Ptw.v`'s own reads** —
   stayed tied to the real LSU's stale `funct3_regem`, truncating 32-bit PTE reads to their low byte.
   Fixed: a `wb_m_funct3` mux forcing word-width during a walk.
5. **Forwarding-window exhaustion.** `Forward.v`'s mux only has a bounded ~2-cycle window after its
   producer retires — a load/store's address held in EX by `dtlb_miss` for longer than that reverted
   to a stale pre-forward operand (an address drifted from `0x1004` to `0x1000`, losing an
   immediate-offset instruction's contribution once it aged out of the window). Fixed: a new
   `dtlb_vaddr_r` latch, mirroring `Divider.v`/`Ptw.v`'s own "latch inputs once at start" discipline —
   the first mechanism in `riscvpipeline.v` to need it, since no other `reg2_hold` source previously
   depended on a value past its first cycle. A same-shape off-by-one followed immediately: gating the
   mux on live `dtlb_miss` instead of the one-cycle-delayed `dtlb_miss_r` read the register one cycle
   too early. Fixed by gating on `dtlb_miss_r`.
6. **The identical drift hit the store's own data operand.** Fixed with a sibling
   `dtlb_store_data_r` latch; the pre-existing `docs/adr/0003` store-data assertion needed updating to
   track the frozen value instead of the raw live expression.

A seventh, related gap (not a bug introduced by F5, but found by this same hand-trace and fixed here
since F5 already touches the exact logic): **`reg3_bubble` never included `exception_taken`.**
Harmless for `illegalOpcode`/`ecall`/`ebreak` (already `regWrite=0`), but `csr_priv_violation` (F3) is
a real `csrrX` instruction with `regWrite=1` — a privileged CSR's value could leak into a user-visible
GPR one cycle before the redirect became visible anywhere else. Fixed: `reg3_bubble = div_stall |
fp_stall | dtlb_miss | exception_taken`.

## Alternatives considered

- **Intercepting D-side translation at `ALUOut_regem` (post-reg3-latch, MEM stage)**, as the phase
  plan's literal wording said. Rejected once hand-traced: by the time a fault would be discovered at
  MEM, EX's own `_regde` signals already describe a different, younger instruction, so redirecting
  from MEM can't reuse `exception_taken` at all and would need its own parallel mepc/cause-selection
  logic — real, but strictly more machinery for no benefit, since `ALUOut` is already fully computed
  combinationally at EX, one cycle earlier.
- **A real bus arbiter for the PTW's second master port.** Rejected: a walk only ever happens while
  the pipeline is already stalled waiting for it, so there is never genuine concurrent contention to
  arbitrate — a plain mux is sufficient and simpler.
- **Split I-TLB/D-TLB.** Rejected: a unified array with two combinational read ports is cheap in
  behavioral Verilog and avoids duplicating the fill/flush logic for no behavioral benefit at this
  scale.
- **PMP-only, deferring full Sv32.** Rejected by the user's own scope decision (most ambitious option,
  consistent with every prior phase).

## Validation strategy

Every step ended with the full suite passing again before moving to the next, the same discipline as
every prior phase:

- **Full directed suite**: grew from Phase E's 50/50 baseline to 60/60 across F1-F7 (new tests:
  `tb_mmu_csr_f1.v`, `tb_mmu_decode_f2.v`, `tb_mmu_priv_f3.v`, `tb_mmu_translate_f5.v`,
  `tb_mmu_csr_leak_f5.v`, `tb_mmu_ifetch_fault_f5.v`, `tb_mmu_dtlb_permfault_f5.v`,
  `tb_mmu_dtlb_unmapped_f5.v`), zero-warning `iverilog -Wall -g2005` compile throughout.
- **F5's directed coverage**: a full 2-level walk on fetch and on load/store, a walk-count tap on
  `m_Ptw.done` confirming exactly the expected number of real walks (no re-walk once the TLB is
  warm), an instruction page fault (`mcause`=12), and the `csr_priv_violation` regWrite-leak fix
  confirmed directly (a U-mode read of an M-only CSR never lets `rd` receive the real value).
- **F7's directed coverage, closing gaps F5 deliberately deferred**: a D-side permission violation
  (store to a read-only page, `mcause`=15) and a D-side unmapped access (`mcause`=13) — the D-side
  siblings of F5's own instruction-fault test.
- **F6**: `sim/tools/iss.py` gained a from-scratch `translate()` matching `Ptw.v` bit-for-bit (2-level
  walk, megapage, all fault conditions, 20-bit PPN truncation per this core's own documented scope
  decision), `trap()`/`mret()` rewritten to bit-level `mstatus` updates (was a blanket overwrite, safe
  only when MIE/MPIE were the sole real bits), new `sret()`, `sfence.vma` decode+privilege check,
  privilege-dependent `ecall` cause and CSR-access checks. Verified directly against the exact
  page-table scenario from F5's own RTL debug session (2-level, megapage, permission fault,
  delegation, misalignment — all matching known-correct values) before any random cross-checking was
  attempted.
- **F7**: `random_gen.py`/`run_random_tests.py` gained an opt-in `--mmu` mode with a
  **generator-guaranteed-valid** page table — never a truly random `satp`, mirroring D10's own "agree
  by construction" philosophy, extended from interrupt-timing agreement to translation-validity
  agreement. Two real bugs found here, both by running: a 12-bit signed immediate overflow once
  `addr_space` grew for MMU mode (fixed by capping offsets at 2047), and a random CSR instruction
  landing on an M-only register while running as U-mode, correctly privilege-trapping to an unset
  `mtvec`=0 and executing raw page-table bytes as garbage (fixed by excluding the `csr` instruction
  kind entirely when `mmu=True`).
- **F8**: the real-volume constrained-random sweep — **150/150 MMU-enabled programs matched the ISS
  reference** at a fresh seed range, and a further 60/60 non-MMU sweep at yet another fresh seed range
  confirmed the pre-existing corpus stays 100% clean throughout, on top of the 100/100 + 40/40
  (profile-1/predictor-1 combo) non-MMU sweeps already run clean after F5 and F6 individually.
- **Bit-exact default confirmed by construction and by running**: every translation substitution
  reduces to exactly the pre-Phase-F expression at `translate_enable=0`, and the entire pre-existing
  corpus (every program never touching `satp`) is unaffected by construction — `mideleg`/`medeleg`/
  `satp` all default to 0.

## Future improvements

- **A tagged TLB, or a larger TLB.** The current unified TLB is sized minimally for this project's own
  small test programs — a larger, more realistic working set was out of scope here, same "minimal, not
  maximal" spirit as prior phases' own scope calls.
- **`mstatus.MPRV`, SUM/MXR bits.** Explicitly out of scope — S-mode can never access U-accessible
  pages under this implementation (the literal SUM=0 behavior with no toggle), a real, spec-legal
  simplification, not an oversight. Future work if a use case actually needs it.
- **Selective TLB invalidation (`sfence.vma` with real `rs1`/`rs2` semantics).** Currently always a
  full flush. Future work if a realistic workload's flush frequency ever makes this matter.
- **Whether Generation 3's later MMU work (per `docs/ROADMAP_VISION.md`) is a genuine RV64/Sv39
  redesign or a port of this phase's RV32/Sv32 `Tlb.v`/`Ptw.v`** — an open question, deliberately not
  answered here; decide when Generation 3 is actually reached.

## Closing out Phase F

Phase F (F1-F9) is done. `docs/ROADMAP.md` and `handoff.md` are updated by this same commit to reflect
its status. Per the Generation 1 scope decision (`docs/ROADMAP_VISION.md`), Phase H (dual-issue) is
dropped from near-term scope; Phase G (caches) is next, reframed as Generation 1's I$/D$ work, and
needs its own dedicated research+design pass before implementation, per this project's own "each phase
gets its own dedicated pass" convention.
